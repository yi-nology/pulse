## 发现（本次 E2E 新增）

| # | 级别 | 描述 | 建议 |
|---|---|---|---|
| E2E-1 | 中 | **reopen 任务从周报"进行中"消失**：本周完成与进行中是互斥 switch，done→reopen(in_progress) 的任务因"本周完成过"不再出现在进行中，与代码注释"正交可重叠"的意图相悖（internal/reports/weekly.go:172-177） | 拆成两个独立 if，允许同任务出现在两节 |
| E2E-2 | 中（可用性） | **CLI 无法把任务指派给 agent 成员**：`task add/update --assignee codex` 恒走 human get-or-create，撞上同名 agent 报类型冲突；产品语义下"人给 agent 派活"是核心场景（internal/cli/task.go:63） | --assignee 先查成员表，命中即用（不强制 human）；未命中再 human 创建 |
| E2E-3 | 低 | **autopush 使双机冲突默认路径退化为纯 LWW**：写后自动推送即时收敛 dirty 状态，sync 期冲突检测只剩离线/推送失败窗口；被覆盖方在 sync 输出中无任何提示（审计需查 activity） | pull 覆盖本地"近期人为修改"时在 sync 输出加显式提示行；属已知 LWW 取舍的 UX 增强 |
| E2E-4 | 低 | **MCP publish_feishu 归因到人类**：桥接 `actor.Resolve(cfg.DefaultActor, "", "")` 未传 PULSE_ACTOR，agent 发起的发布落款/返回 actor 均为人类（internal/cli/mcp.go:70） | 桥接仿照 AutopushFunc 把 agent 名传入 |

（以上均为不阻塞使用的打磨项，已并入 post-merge-notes.md 的跟进清单。）

## 结论

**全部承诺场景在真实二进制 + 完整 HTTP 链路上跑通**：人用 CLI、agent 用 MCP、飞书当同步中枢与沉淀地、双机对抗（互拉互推/冲突 LWW/软删传播/archived 拒绝）符合设计。唯一需要真实飞书租户确认的是仿真服务器无法覆盖的平台行为细节（甘特视图对 text 日期列的实际渲染、真实限流节奏），已在 post-merge-notes.md 列为首次真实使用前的人工检查项。
