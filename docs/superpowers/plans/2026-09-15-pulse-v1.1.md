# Pulse v1.1（研发交付闭环）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地 spec §3.1-3.2 的研发交付闭环六实体（需求/评审/会议/bug/提测单/发版记录）+ 协作记录文档模板 + 对应 CLI/MCP 工具 + 多维表格同步扩展。

**Architecture:** 完全复用 MVP 既有模式——store 层事务+activity 审计（仿 tasks.go）、CLI cobra 命令（仿 task.go/version.go）、MCP 工具薄封装（仿 mcpserver/server.go 的 actor/归因/autopush 钩子）、飞书 adapter（bitableAPI 接口 + fakeAPI 测试、publish 的块构造）。协作记录（评审/会议/提测/发版/需求长文）按"pulse 管结构/状态/链接，内容按模板建飞书文档多人协作，不回流"落地。

**Tech Stack:** 不变（Go 1.25、modernc sqlite、cobra、go-sdk、net/http 飞书直连）。

**Spec:** docs/superpowers/specs/2026-09-14-pulse-mvp-design.md §3.1-3.2、§6（sync 范围）

## Global Constraints（继承 MVP 全部约束，另加）

- 六实体 schema 以 spec §3.1 为准逐字落地；状态枚举不得增减
- 实体写路径全部落 activity（entity_type = requirement/review/meeting/bug/test_submission/release）
- 协作记录文档**永不解析回流**；状态流转只经 CLI/MCP 显式操作
- 模板文档由 feishu adapter 创建（owner=应用），token 回填实体行；未配置飞书时该实体仍可无文档使用（token 空）
- sync 新表沿用：软删（已废弃）、ContentHash 回声、per-table 水位、pending_record 幂等——复制现有 tasks 模式，不改既有表

### Task 1: 六实体 store（schema + CRUD + activity）

**Files:** internal/store/{requirements,reviews,meetings,bugs,submissions,releases}.go + 迁移 + 各 _test.go

**Interfaces（后续任务依赖，精确签名）:**

```go
// 需求：status: proposed|reviewing|accepted|in_dev|delivered|rejected
func (s *Store) CreateRequirement(r model.Requirement, actor model.Member, behalf *model.Member) (model.Requirement, error)

// reviews: kind: requirement|release|test；conclusion: pending|passed|passed_with_notes|rejected
func (s *Store) CreateReview(v model.Review, actor, behalf) (model.Review, error)
func (s *Store) ListReviews(projectID int64, requirementID int64) ([]model.Review, error) // requirementID=0 全部
func (s *Store) UpdateReviewConclusion(id int64, conclusion string, actor, behalf) (model.Review, error)
// meetings
func (s *Store) CreateMeeting(v model.Meeting, actor, behalf) (model.Meeting, error)
func (s *Store) ListMeetings(projectID int64) ([]model.Meeting, error)
// bugs: severity 1..4(P0-P3)；status: open|fixing|fixed|verified|closed|wontfix
func (s *Store) CreateBug(v model.Bug, actor, behalf) (model.Bug, error)
func (s *Store) GetBug(id int64) (model.Bug, bool, error)
func (s *Store) ListBugs(projectID int64, f BugFilter{Status, Severity, AssigneeID, VersionID}) ([]model.Bug, error)
func (s *Store) UpdateBug(id int64, ch BugChanges, actor, behalf) (model.Bug, error)
// test_submissions: status: draft|submitted|testing|passed|failed
func (s *Store) CreateTestSubmission(v model.TestSubmission, actor, behalf) (model.TestSubmission, error)
func (s *Store) ListTestSubmissions(projectID int64, versionID int64) ([]model.TestSubmission, error)

func (s *Store) ListReleases(projectID int64) ([]model.Release, error)
func (s *Store) UpdateRelease(id int64, ch ReleaseChanges, actor, behalf) (model.Release, error)
```

- schema 按 spec §3.1 逐字（含 requirement_id 外键加到 tasks：`ALTER TABLE tasks ADD COLUMN requirement_id INTEGER` 容忍已存在；新表 CREATE TABLE IF NOT EXISTS）；六实体均有 `feishu_doc_token` 列（meeting/review/submission/release/requirement）与 `bitable_record_id/bitable_synced_hash/synced_at/archived`（sync 扩展用，与 tasks 对齐）
- 全部写路径事务内落 activity（同 tasks.go 模式，execer 复用）；状态流转 detail `{"field":"status","from":..,"to":..}`；bug fixed→非fixed 不特殊化（无 reopen 规则）

### Task 3: 协作记录文档模板（feishu/records.go）

**Files:** internal/feishu/records.go + records_test.go；cli 各命令加 `--doc` 自动创建（默认：create 即建文档；`--no-doc` 跳过）

- 复用 api.go 的 DocCreate/BlockAppend 与 publish.go 的块构造常量。5 套模板（heading2 标题 + bullet 字段行 + todo 清单）：
  - 需求文档：标题 `需求 · <title>`，节：背景/描述(bullet)、状态与负责人、关联任务提示"行动项请用 pulse task add --requirement"
  - 评审纪要：`评审记录 · <kind> · 需求#<id|->`，节：参与人与时间、结论（pending 占位）、行动项 todo 块
  - 会议纪要：`会议纪要 · <title>`，节：时间/参会人、讨论要点(bullet 占位)、行动项 todo 块
  - 提测单：`提测单 · <version> · #<id>`，节：提测人/测试负责人、范围(scope)、自检清单(todo 块：冒烟通过/核心路径回归/数据兼容)、风险
  - 发版记录：`发版记录 · <version>`，节：发布负责人、检查清单(todo：测试通过/回滚方案确认/发布公告)、状态与时间
- `EnsureRecordDoc(ctx, c *Client, s *Store, entityKind string, id int64, actorName string) (docToken string, err error)`：token 已存在→直接返回；否则建 doc+模板块+回写实体行（各 Update* 的 doc-token 通道或专用 store setter）+ activity `action="feishu_record_doc"`。未配置飞书 → 返回引导错误（CLI 捕获后降级为提示"已保存记录（无文档）"）
- **[ ] TDD**：fakeAPI 断言每种模板的块顺序/标题文本/回写；幂等（已有 token 零调用）；未配置降级
- **[ ] Commit** `feat(feishu): collaborative record doc templates`
